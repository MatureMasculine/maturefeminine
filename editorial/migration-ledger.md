# Migration Ledger

## Scope and rules

This ledger has **72 legacy entry rows**: every one of the 21 current archetypes and 42 current shadows, followed by the three restored historical archetypes and their six shadows. Many-to-one merges preserve all legacy rows while producing **22 canonical parents, 44 canonical shadows, and 66 canonical spreads**. Parent destinations use `/<lifecycle>/<parent>/`; shadow destinations use `/<lifecycle>/<parent>/shadows/<shadow>/`.

Operations describe identity changes:

- **retain** keeps the canonical slug and lifecycle.
- **rename** changes a title or slug without changing the psychological function.
- **move** changes the lifecycle or canonical lifecycle route.
- **restore** returns an entry found in the last pre-Markdown canonical data.
- **replace** is reserved for a concept, quality pair, or asset that cannot survive as-is.
- **merge** maps a legacy row into another canonical parent or shadow while preserving its alias, route behavior, content disposition, and image candidacy.
- **retire** removes an identity from the canonical set while preserving its historical disposition.

Current shadow URLs are fragment identifiers inside parent pages, not server-visible paths. Their legacy behavior must therefore be implemented as an anchor shim on the destination parent, plus a reserved old-slug alias for any standalone path encountered later. A server cannot issue a fragment-specific redirect.

## Migration invariants

- Generated JSON is regenerated from Markdown and never edited by hand.
- Each legacy parent route receives exactly one canonical destination.
- Each old shadow fragment remains resolvable by a destination-page anchor shim even though fragments cannot be redirected by the server.
- Alias support is for findability, not permission to show compound titles in navigation, headings, metadata, or the printed book.
- Cultural and mythic names retained in historical titles, filenames, or migration notes are internal provenance, not reader-facing aliases or body copy. They may print only as verified Mythic Resonances profile values. Parent and shadow assignments remain separate: each shadow requires its own shadow-specific value and independently verified research/source identifiers and never inherits a parent figure.
- An image remap is provisional until thematic fit, cultural context, rights, resolution, and print rendering pass the artwork gates.
